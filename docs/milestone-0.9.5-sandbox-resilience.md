# Веха 0.9.5: обработка недоступности песочницы

- **Статус:** [x] Завершена; [приёмка и ограничения](milestone-0.9.5-acceptance-2026-09-09.md).
- **Приоритет:** MAJOR.
- **Цель:** безопасно переживать недоступность брокерской песочницы и
  автоматически восстанавливать работу после возвращения пригодных данных.

## Постановка

В наблюдении 0.9.3 зарегистрированы gRPC UNAVAILABLE и примерно минутное окно
без свежих рыночных снимков. Возможна недоступность самой песочницы; внешняя
причина не установлена. По уточнению пользователя её расследование не входит
в обязательный объём и не является условием приёмки этой вехи.

Нужен проверяемый контракт поведения приложения при таком сбое. Существующие
механизмы следует переиспользовать; изменения требуются там, где тест выявит
пробел. Новая стратегия, дополнительные поля бюджета и ослабление TTL не нужны.

## Требуемое поведение

1. **Обнаружение и изоляция.** Обрабатывать разрыв соединения, временный отказ
   запроса и поток, который остаётся подключённым, но перестал давать пригодные
   данные. Свежесть оценивать по времени самих данных. Отсутствие событий само
   по себе не доказывает отказ песочницы. Устаревший инструмент не должен
   блокировать обработку остальных инструментов со свежими данными.
2. **Безопасное ожидание.** Новые торговые заявки по устаревшему или недоступному
   снимку не создаются. Сохранённые intent, исполнения и outbox не теряются;
   heartbeat и доступные операции сверки/доставки продолжаются. Недоступность
   брокера не должна превращать неопределённый исход заявки в повторную отправку.
3. **Ограниченные повторы.** По последнему уточнению пользователя интервалы
   повторов составляют **1, 3, 5, 7, 9 секунд**: шаг 2 секунды, без случайного
   разброса. `SANDBOX_RETRY_LIMIT` задаёт число повторов после первой попытки,
   по умолчанию 5; значение 0 разрешает только первую попытку. При другом числе
   повторов интервал повтора с номером N равен `2 × N − 1` секунд.
   После исчерпания попыток источник приостанавливается; polling не запускает
   новый цикл. Повторные сигналы сбоя не создают параллельных подключений.
   Невосстановимые ошибки конфигурации или авторизации не маскируются бесконечным
   быстрым повтором. Используются согласованные endpoint и SDK.
4. **Возобновление.** При доступном бюджете повторов после восстановления соединения заново получить необходимые
   подписки и рыночный контекст. Допуск новых действий возвращается только после
   существующих проверок свежести, полноты данных и состояния исполнения.
   Пользовательский HOLD и другие действующие запреты автоматически не снимаются.
   Исчерпание попыток и невосстановимые ошибки требуют смены конфигурации Core
   либо перезапуска соответствующего runtime; заблокированный Worker требует
   перезапуска после устранения причины. Счётчик нового эпизода сбрасывается
   после подтверждённого восстановления, а не одного успешного открытия канала.
5. **Наблюдаемость.** По безопасным кодам, счётчикам и временным меткам различать
   недоступность данных, попытки восстановления и возврат готовности. Фиксировать
   время обнаружения и восстановления без токенов, исходных ответов брокера
   и потока повторяющихся одинаковых сообщений.

## Проверки и DoD

- Детерминированные изолированные сценарии: отказ при первом подключении,
  разрыв рабочего потока, длительное отсутствие свежих данных, несколько
  последовательных отказов и успешное восстановление.
- Проверены ограничение повторов и отсутствие конкурирующих переподключений;
  пока данные устарели, новых заявок нет. Здоровые инструменты продолжают работу.
- Проверены точный ряд задержек, шесть суммарных попыток при значении 5,
  настройки 0/2/5, остановка после исчерпания и отсутствие обхода лимита при
  повторном запросе снимка или переподключении источника.
- После восстановления корректные решения возобновляются; накопленные факты
  доставляются без потерь и дублей, неопределённые заявки проходят штатную сверку.
- Проверены перезапуск Worker во время недоступности и сохранение явного HOLD.
- Для воспроизводимых сценариев измерены время обнаружения, интервалы повторов
  и время до первого допустимого решения; интервалы соответствуют выбранной
  политике восстановления. Production SLA заранее не объявляется.
- Регрессия и независимое кросс-ревью саб-агентами по SOLID и чистоте кода пройдены.

При доступной песочнице выполняется дополнительная проверка в Compose.
Недоступность внешней среды не блокирует приёмку проверенного поведения:
операционное подтверждение фиксируется отдельно от изолированных тестов.

## Границы

Установление причины сбоя на стороне провайдера, непрерывная доступность
песочницы и изменение лимитов внешнего API не являются результатами этой вехи.
Диагностика приложения нужна в объёме, необходимом для проверки обработки сбоя.
Профилирование доставки на PostgreSQL остаётся отдельной задачей 0.9.4.

Основание: [приёмка 0.9.3](milestone-0.9.3-acceptance-2026-09-09.md).
