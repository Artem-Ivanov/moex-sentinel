# Приёмка 0.2: владение данными и целостность фактов

Статус: завершена 2026-09-09, обновлённый Core развёрнут в локальном Compose.

## Результат

Зафиксирована [карта владения данными](data-ownership.md) текущей baseline-схемы:
Core PostgreSQL принимает факты через единый typed ingress, Worker SQLite хранит
восстановимое состояние исполнения и outbox, Analytics не имеет постоянного
хранилища. Исторические shadow-этапы дорожной карты отделены от текущего runtime;
их продолжение заменено согласованным запуском с пустой БД.

Исправлены два нарушения связности внутри одного подключения брокера:

- `PositionLedgerRepository.open_cycle` отклоняет цикл, если его инструмент
  отличается от инструмента автомата. Используется существующий `INVALID_STATE`,
  который ingress переводит в `INVALID_FACT_STATE`.
- `TradingAnalyticsRepository.append_position_valuation` проверяет общую связь
  оценки, цикла, автомата и инструмента; несовпадение отклоняется как `CROSS_SCOPE`.

Проверки выполняются в repository, поверх существующих scoped FK. Новых миграций
нет. Произвольный SQL в обход repository не получает дополнительных ограничений.
Сейчас valuation repository не имеет production-вызова; его контракт защищён
для дальнейшего использования.

## Проверки

До исправления новые тесты воспроизводили принятие неверного цикла и оценок.
После исправления SQLite и PostgreSQL подтверждают полный откат группы фактов:
состояние, revision и sequence сохраняются, частичные envelopes и cycle не остаются.
Исправленная группа с теми же идентификаторами принимается; точный повтор не
дублирует данные. Valuation-тесты проверяют также несовпадение инструмента
между уже сохранённым циклом и его автоматом.

Новый `tests/integration/postgresql/test_schema_constraints.py` сравнивает
мигрированную схему с независимой ORM-схемой, нормализованной PostgreSQL:
состав FK и ON DELETE, UNIQUE, колонки/уникальность/условия индексов.
Расхождений нет. Сравнение CHECK-выражений в этот тест не входит.

Финальные результаты:

- Полная Python-регрессия с PostgreSQL: **953 passed**, без пропусков,
  17 существующих предупреждений SDK/Starlette.
- Скрипты и проверки `develop/tests` с PostgreSQL: **48 passed**.
- Ruff и Black для семи изменённых/новых Python-файлов: успешно.
- `mypy --python-executable .venv/bin/python src/trading_automaton/composition.py`:
  успешно, один явно проверенный исходный файл.

PostgreSQL-тесты использовали отдельный контейнер `moex-sentinel-phase0-tests`,
порт localhost 55439, временное хранилище tmpfs и отдельные схемы для тестов.
Рабочая БД не использовалась для миграционных тестов. После проверки одноразовый
контейнер остановлен и удалён.

## Локальное развёртывание

До обновления read-only проверка рабочей Core БД выявила 15 циклов и ноль
нарушений их связности; valuation-записей нет. Восстановление данных не требовалось.

Образ Core пересобран. Worker штатно остановлен на время замены Core, после
успешной проверки здоровья возобновлён; nginx перечитал конфигурацию.
Все шесть сервисов работают, четыре имеющие healthcheck — healthy.
Публичный `/api/health` подтверждает `database=ok`, `schema=compatible`.

Probe 12:52:13–12:52:20 UTC: шесть автоматов IN_WORK, **16 новых решений**,
очередь outbox опустела. Во всех восьми проверках Analytics UNAVAILABLE=0;
свежими были 4–6 инструментов из шести, в двух проверках — все шесть.
В последней проверке один стакан устарел, поэтому команда с
`--require-all-fresh` завершилась с кодом 1. Непрерывная свежесть всех инструментов
не подтверждена; строгий TTL продолжает отсекать устаревшие данные.
Это известное ограничение рыночного потока, не критерий целостности БД вехи 0.2.

Рабочие PostgreSQL/SQLite volumes и журналы коррекции цен сохранены.
Стратегия остаётся единой и определяется кодом; новых полей бюджета позиции нет.
