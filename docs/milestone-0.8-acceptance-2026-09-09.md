# Приёмка 0.8 — механика принятия решений

Дата: 2026-09-09. Статус: завершена, включая исправление конфликта metadata,
восстановление outbox и повторное развёртывание Worker.

## Реализованный результат

1. Стакан проверяется до изменения pending_low/rearm. Все цены конечны и
   положительны, количества положительны, порядок уровней корректен.
   Проверяются consistency, crossed book, TTL и будущие метки времени.
2. Покупки требуют готового существующего окна SMA5/SMA20/change10 и диапазона,
   наблюдённого минимума и разворота. Последние 20 завершённых минутных свечей
   непрерывны; порядок, дубли и конфликтующие свечи обработаны явно.
3. Downtrend и верхняя четверть диапазона фильтруют первичный вход и усреднение.
   Шаг усреднения проверяется по исполнимому ask. Доступные средства включают
   комиссию покупки.
4. Полный take-profit считается по best_bid после входной и выходной комиссий;
   входная комиссия распределяется по оставшимся лотам. Stop-loss, частичный
   выход, адаптивные формулы и числовые настройки сохранены.
5. Ненулевое BUY/SELL-исполнение обновляет цикл атомарно с terminal intent,
   lot ledger и outbox. BUY сохраняет свечу решения, SELL меняет готовность
   следующей продажи. Zero-fill и exact replay не повторяют переход.
6. SQL CAS сравнивает исходный цикл до наблюдения. Устаревший WAIT не стирает
   исполнение, устаревшее торговое решение превращается в
   WAIT/CYCLE_STATE_CHANGED без intent и dispatch. Проверены обе стороны,
   свежий rearm и точность времени SQLite.

## Принятые трактовки

- Подтверждённое микро-окно — существующий SMA20, без нового параметра.
  Неполный или разорванный хвост задерживает покупки до готовности окна.
- Цель полного take-profit трактуется как чистая прибыль после комиссий;
  это может отложить полный выход относительно прежнего gross-порога.
- Нестабильность здесь означает invalid/inconsistent/stale; новый фильтр
  величины ценового скачка не вводится. Поздняя обработка использует единый
  snapshot.created_at для cycle, scheduler и materialization.
- Для finite stale/crossed/inconsistent сохраняются WAIT и audit с причиной.
  Empty/NaN дают структурированное предупреждение без ценового position-факта;
  соседние позиции продолжают обрабатываться.
- Идемпотентность запрещает дублирующий intent и повторную покупку в той же
  свече после fill. WAIT/audit остаются журналом наблюдений и могут повторяться.
- Runtime передаёт исходный цикл для CAS. Для legacy batch без baseline
  сохранены проверки времени и BUY-маркера; новый runtime этим путём не пользуется.

## Развёртывание

Worker штатно остановлен с кодом 0; Core, сборщик снимков и Worker обновлены,
nginx перечитал адрес backend. Схема БД и оба persistent volume сохранены.
API через frontend сообщает database=ok и schema=compatible, снимок портфеля
доступен без ошибок сводки, стратегия включена.

Первый срез после обновления показывал шесть IN_WORK без UNCERTAIN. Последующее
наблюдение выявило FAILED-группы: приватный decision_candle_at попал в
strategy_snapshot последующих событий заявки, хотя initial event его не
содержал. Core отклонил изменение неизменяемого snapshot. Worker штатно
остановлен; исправление использует исходный decision.strategy_snapshot для
Core, а candle metadata сохраняет в LocalIntent. Два интеграционных теста
проверяют реальную доставку initial/SUBMITTING/FILLED graph, в том числе при
ранее принятом initial event, exact retry и ACK.

Скрипт `develop/scripts/repair_decision_candle_facts.py` проверил три группы,
исправил приватное поле в девяти непринятых событиях и доставил все 78 фактов
с прежними event_id и sequence. Core подтвердил все события; cache восстановлен
из авторитетных статусов без команд resume и повторной отправки брокерских
заявок. Повторный dry-run вернул ноль групп. Временный ID/sequence-журнал
удалён после ACK, production-схема не изменена.

После повторного запуска Core и Worker согласованы: шесть IN_WORK, нет
UNCERTAIN. На контрольном срезе outbox пуст, FAILED отсутствуют, API healthy,
ошибок сводки нет. Суммарная последовательность принятых фактов — 199 215.
Следующая проверка подтвердила рост до 203 371, FAILED=0 и отсутствие
повторных попыток у текущей очереди. Временный тестовый PostgreSQL удалён.
