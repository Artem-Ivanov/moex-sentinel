# Кэш снимка брокерского счёта

## Цель

Исключить повторные запросы портфеля и свободных средств в каждом секундном цикле воркера, не разрешая торговые решения по неподтверждённому или просроченному состоянию счёта.

## Решение

Внутри одного broker-runtime хранится последний успешно полученный снимок счёта. Снимок включает позиции и свободные средства по валютам и имеет TTL 60 секунд. Ключ кэша — идентификатор брокерского счёта.

Redis в текущую реализацию не добавляется: runtime запускается в одной реплике, а кэш не должен переживать перезапуск процесса. Интерфейс кэша остаётся локальным и допускает будущий Redis-адаптер, если появятся несколько реплик воркера.

## Поток данных

1. При старте broker-runtime кэш пуст, поэтому до первого торгового тика запрашивается свежий снимок счёта.
2. Пока снимок моложе 60 секунд, подготовка тика, проверка свободных средств и reconciliation используют один и тот же снимок без дополнительных запросов портфеля.
3. После терминального состояния ордера (`FILLED`, `REJECTED`, `CANCELLED`) снимок соответствующего счёта инвалидируется. Следующий тик обязан получить новое состояние.
4. После истечения TTL снимок обновляется один раз на счёт, даже если в нём несколько автоматизаций.
5. Позиции, не прошедшие валидацию торгового инструмента, включая балансовые строки наподобие `RUB000UTSTOM`, не создают автоматизации, циклы или лоты.

## Ошибки и безопасность торговли

Если обновить отсутствующий или просроченный снимок не удалось, торговая подготовка этого счёта считается незавершённой. Воркер сохраняет broker-runtime, применяет контролируемую паузу и повторяет обновление позднее; торговые решения по старому снимку не выполняются.

Временный ответ брокера `RESOURCE_EXHAUSTED` не должен завершать runtime и запускать цикл его пересоздания. Неожиданные программные ошибки не маскируются обработчиком временных ошибок.

## Проверки

- два тика в пределах TTL выполняют один запрос состояния счёта;
- несколько автоматизаций одного счёта используют общий снимок;
- истечение TTL вызывает одно обновление;
- терминальное состояние ордера инвалидирует снимок;
- после перезапуска требуется свежий снимок независимо от предыдущего процесса;
- при ошибке обновления просроченный снимок не допускает торговый тик;
- reconciliation не выполняет отдельный запрос портфеля;
- невалидная позиция исключается из стартового состояния.
