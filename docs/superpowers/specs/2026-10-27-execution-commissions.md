## Effective Core финансовый результат
Один scoped repository рассчитывает raw ledger + cumulative fee overlay для всей истории автомата, включая закрытые lots/cycles. Не вычитать lifetime correction из единственного открытого cycle. BUY correction распределяется по original_lots между allocations и open remainder; SELL — по executed_lots allocations. Последняя доля получает Decimal remainder. Closed доля уменьшает realizedPnL, open entryfee — netPnL; actual commissions учитывают поправку один раз. Unknown/coverage не скрывать: явный financial status, неполные суммы не называть полным PnL. Portfolio equity summary/admission daily loss уже содержат комиссии и НЕ получают второй debit.

Raw execution diagnostics сохраняют broker_commission первоначального факта и отдельно показывают effective_broker_commission/commission_status, чтобы изменение можно проверить. Не подменять immutable факт исправленной суммой.

Публичный AutomationRecord/View `/api/trading-automations` получает `financial_status: COMPLETE|INCOMPLETE|UNKNOWN`. Существующие страницы списка/деталей печатают PnL и комиссии, поэтому должны показать короткое пояснение для INCOMPLETE/UNKNOWN рядом с этими суммами; клиент не пересчитывает деньги и не добавляет допуск торговли. Legacy response без поля совместим. Это небольшой пакет существующего интерфейса, без redesign/зависимостей. Для него при release обновляется только PROD frontend, TEST frontend не трогаем.
