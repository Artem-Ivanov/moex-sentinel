# Веха 0.8: механика решений

## Цель и границы

Закрыть DoD 0.8 на существующем streaming runtime: проверенный стакан до
изменения цикла, подтверждённый вход, комиссии и устойчивость повторной обработки.
Параметры окружения, адаптивные формулы и размеры покупки сохраняются.
Core API, схема PostgreSQL и торговые volumes не меняются. Legacy planner
сохраняет совместимость, новый альтернативный runtime не создаётся.

## Рыночный контекст

Единая проверка стакана предшествует наблюдению pending_low/rearm и решению.
Пустые, inconsistent, crossed, просроченные и структурно некорректные книги
не могут изменять цикл или создавать заявку. Валидируются конечные положительные
цены, положительные количества и порядок уровней; будущая временная метка
отклоняется. TTL остаётся две секунды, точная граница допустима.
Cycle, scheduler и materialization используют один snapshot.created_at.
Для finite stale/crossed/inconsistent сохраняются WAIT и audit с причиной.
Empty/NaN не дают ценового position-факта; причина регистрируется в
структурированном warning без цен, соседние позиции обрабатываются дальше.
Нестабильность в этой вехе — inconsistency/invalid/stale, без нового порога
ценового скачка или фильтра волатильности. Это сохраняет нормативную стратегию.

Подтверждённое окно покупки — готовый существующий контекст SMA5/SMA20,
изменения за 10 свечей и диапазона завершённых минутных свечей, плюс
наблюдение минимума и последующий разворот по существующей формуле.
Отсутствие данных не трактуется как боковой рынок. Первое наблюдение с пустым
pending_low даёт WAIT. Окно расчёта нормализуется по уникальным временам
завершённых свечей; порядок входного списка не влияет на индикаторы.
Последние 20 минут должны быть непрерывными; конфликтующие записи одного
времени исключаются. Дыра требует нового непрерывного хвоста из 20 свечей.

## Решения

Покупка при недостатке индикаторов даёт WAIT. Фильтр падающего тренда и
существующая верхняя четверть диапазона применяются к первичному входу и
усреднению; новых порогов не вводится. Усреднение сохраняет шаг цены,
подтверждение разворота, cooldown свечи и проверку доступных денег с комиссией.
Шаг усреднения проверяется по исполнимому ask.

Stop-loss сохраняет приоритет и прежний ценовой порог. Полный take-profit
проверяет достижение установленного процента после комиссии покупки и
ожидаемой комиссии продажи, по исполнимому best_bid. Частичная продажа
сохраняет существующий расчёт чистой прибыли по лоту, пороги и rearm цикла.
Невыполненный полный take-profit не подавляет допустимую частичную продажу.

## Исполнение и повторение

Реальное ненулевое BUY-исполнение очищает pending_low и сохраняет свечу
решения как last_buy_candle_at. Ненулевое SELL-исполнение обновляет sell arm
и последнюю цену продажи. Изменения цикла, terminal intent, lot ledger и
outbox коммитятся одной транзакцией; exact replay не меняет цикл повторно.
Отмена/отклонение без исполнения не считаются покупкой или продажей.
Метаданные свечи передаются через существующий JSON, без новой колонки.

Повторная обработка одного интервала не создаёт второй intent при активной
заявке; после BUY-исполнения повторная покупка в той же свече запрещена.
Повторные WAIT/audit допустимы: журнал наблюдений не дедуплицируется по времени.
Для старых intent без свечного metadata применяется явно проверяемый fallback
по времени исполнения; повтор не может переместить marker назад.

## Приёмка

Матрица BUY_MORE/SELL_PART/SELL_ALL/WAIT для боковика, роста, падения;
неполное окно, первый тик, разворот, комиссии на границе, invalid/stale book;
реальная транзакция исполнения и повтор после reopening SQLite.
Независимый review, полная Python-регрессия с отдельным PostgreSQL,
Ruff/Black и документационные проверки. Обновление Compose — после тестов,
штатная остановка Worker и сохранение существующего HOLD/UNCERTAIN.
