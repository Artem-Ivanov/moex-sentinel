# Завершение текущей вехи

Исполнение: Superpowers Subagent-Driven Development; исправления проверяются
регрессионными тестами и независимым ревью.

Основание: clean-slate typed runtime, trading summary и portfolio snapshot
forward migration из существующих specs/plans. Новая продуктовая веха не добавляется.

## Границы работы

- Сохранять исходное рабочее дерево и index: репозиторий ещё не имеет HEAD.
- Не запускать торговые действия для проверки; использовать синтетические fixtures.
- PostgreSQL проверять в отдельном временном контейнере без persistent volumes.
- Не удалять и не переключать существующие Core/Worker volumes.
- Не объявлять прежний runtime acceptance повторно выполненным по результатам тестов.

## Решения по исполнению

Исходное дерево используется непосредственно, потому что пользователь просит
завершить находящиеся в нём незакоммиченные изменения, а базы для worktree нет.
Коммиты и публикация не являются частью этой проверки.

Существующие планы применяются как требования. Их исторические пункты RED и
commit не отмечаются задним числом как выполненные в этой сессии.

Все исходные 9 PostgreSQL integration tests выполнены на версиях 17 и 16.
Версия 16 соответствует Compose. При первоначальной проверке стека и volumes
проекта в доступном Docker не было. По последующему прямому запросу пользователя
созданы оба отсутствующих volume, применены миграции и запущен новый Compose-стек.
Прежний deployed volume не мигрировался в этой сессии.

Алгоритм периодов сохраняется: последний общий снимок перед границей или
первый общий снимок при недостатке истории, с фактическим `from` в API.
Это соответствует существующему плану и regression tests. При длительном
перерыве номинальный период будет приближённым; ограничение описано в
документации вместо введения произвольного порога свежести.

Во время проверки сборки обнаружено внешнее изменение первой строки
`pyproject.toml`, нарушившее TOML. Удалён только лишний ведущий символ;
wheel и sdist затем успешно собраны.
