# Проверка устойчивости и производительности — план реализации

> **For agentic workers:** Use superpowers:subagent-driven-development; independent review is required.

**Goal:** закрыть остатки приёмки 0.1/0.6 и получить воспроизводимые измерения
приложения на 6/20/50 инструментах вместе с наблюдением локального runtime.

**Architecture:** существующие Analytics, Worker composition, SQLite/outbox и
Core ingress проверяются с синтетическим брокером в временных БД. Рабочий Compose
наблюдается отдельными read-only диагностическими скриптами.

**Tech Stack:** Python, Pydantic, pytest, SQLAlchemy, SQLite, ASGI, Vue, Playwright.

**Spec:** согласованный в разговоре следующий этап: UI/dataclass closeout,
наблюдение текущего контура, изолированный benchmark и исправления по измерениям.

## Ограничения

- Вспомогательные программы, результаты и тесты находятся в `develop/`.
- Benchmark не получает реальные credentials, не отправляет внешние заявки
  и не использует рабочие БД. Его временные хранилища удаляются после выполнения.
- Стратегия остаётся единой в коде, новые настройки ресурсов не вводятся.
- Отчёт различает время Worker, доставку фактов и время запроса Analytics.
  SLA заранее не назначается; внешняя сеть и PostgreSQL не моделируются SQLite benchmark.
- Измерения 10 минут — ограниченное наблюдение, не доказательство суточной
  устойчивости. Интервал 5 секунд может пропустить короткие сбои.
- Git index и пользовательские изменения сохраняются; репозиторий без HEAD.
