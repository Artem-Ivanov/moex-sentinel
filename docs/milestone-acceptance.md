# Приёмка вехи — 2026-09-08

Инженерная часть clean-slate runtime, сводка торговли и forward migration
завершены. Локальное окружение запущено через `compose.yml` по запросу пользователя.
Изменения оставлены в рабочем дереве; Git index и история не изменялись.

## Исправления

- Bootstrap-факты передаются неделимой группой при любом положительном
  batch size; Core отвергает неполную или противоречивую начальную группу
  без частичной записи. Следующие факты доставляются отдельно.
- ACK префикса сохраняет локальную ревизию последующих фактов.
- Подготовка портфеля, рынка и комиссий предшествует активации. До подтверждения
  Core команда остаётся HOLD для торговых тиков. CLOSED с активной заявкой
  сохраняет сверку состояния заявки без торговых тиков.
- Повторное принятие позиции после CLOSED создаёт новые устойчивые UUID
  automation/cycle/lot и сохраняет историю прежних поколений.
- Сбор снимков сериализован между минутными интервалами. Повторные и устаревшие
  запуски пропускаются, невалидные суммы одного счёта не отменяют остальные,
  денежные движения во время чтения не записываются как известный P&L.
- Миграция блокирует таблицы до проверки пустоты; поддерживается percent encoding
  в URL Alembic. Документация использует текущий head и правильный порядок сборки
  базового Docker-образа.
- Ошибки сохранения/удаления брокера больше не скрывают список и позволяют повтор
  действия; отмена очищает ошибки формы.
- При Docker-сборке выявлена и исправлена транзитивная зависимость `nanoid`:
  совместимое обновление `3.3.17` → `3.3.18` только в frontend lockfile.

## Запущенное окружение

- URL: `http://localhost:8080`.
- Сервисы: database, backend, frontend, portfolio-snapshot-worker, trading-automaton.
- Database, backend и frontend имеют статус healthy; оба Worker работают.
- Созданы volumes `moex-sentinel-postgres-data` и `moex-sentinel_automaton-data`.
- В рабочей PostgreSQL подтверждена ревизия `0002_portfolio_snapshot_runs`.
- `/` отвечает HTTP 200; `/api/health` сообщает `ok` и совместимую схему.
- `/api/trading/summary` возвращает сохранённый снимок без ошибок; Worker получает
  HTTP 200 от typed command endpoint Core.

Это новое окружение с пустой брокерской конфигурацией. Проверки с фактическими
брокерскими позициями и исполнением заявок в этой сессии не выполнялись.
Прежних volumes не было в доступном Docker; исторические данные не переносились
и не удалялись.

## Практические ограничения

Сводка использует дискретные снимки: API возвращает фактический `from`, который
при перерыве сбора может быть раньше номинальной границы периода. Broker API
не предоставляет атомарный timestamp портфеля вместе с операциями; защита от
движений во время чтения не устраняет задержанную видимость операций у брокера.
