P&L исправлены. Рыночный поток восстановился, Worker создаёт новые решения,
доставка фактов подтверждена. Непрерывная свежесть всех шести инструментов

Уточнение расследования: независимый HTTP/2-клиент получил
`grpc-status: 12 / METHOD_NOT_FOUND` перед `RST_STREAM 8`. SDK 1.49.3 уже
актуален; непосредственно после отключения VPN и перезапуска отказ сохранялся.
Около 12:01 UTC тот же поток снова начал передавать данные. Причина отказа
и восстановления не установлена; SDK, endpoint и credentials не менялись.
[Доказательства и воспроизведение](../develop/market-stream-investigation-2026-09-09.md).

## Реализация

Core поддерживает постоянный рыночный stream и историю минутных свечей.
Отдельный Analytics получает только market DTO и возвращает Worker стакан,
свечи и показатели одного поколения. Worker использует batch HTTP и проверяет
TTL до подготовки решения, после неё и перед отправкой заявки. При истечении
TTL после сохранения intent выполняется локальная отмена без SDK-вызова;
tracking освобождает резерв, а Core принимает соответствующие факты.

Analytics не получает credentials, портфель и состояние заявок;
постоянные Docker volumes к нему не подключаются.
Его Docker-образ не содержит импортируемые пакеты Core и Worker. Alembic head
остался `0002_portfolio_snapshot_runs`; external volumes сохранены. Отдельное
восстановление P&L добавило постоянную maintenance-таблицу
`execution_price_repair_journal` в Core и Worker вне Alembic.

## Дополнительные исправления пользователя

- Детали инструмента: минутные завершённые свечи за последние два часа
  обновляются раз в минуту. Кэш ограничивается текущим окном, параллельные
  запросы не накапливаются, таймер останавливается при уходе со страницы.
- Net P&L: исправлено различие цены единицы в ответе отправки заявки и
  суммы исполнения в ответе опроса статуса. Проверены Core и Worker adapters,
  включая частичное исполнение. Ошибка подтверждена для AFKS и GAZP.
- Net P&L учитывает оплаченные комиссии оставшихся открытых лотов без
  повторного вычитания комиссий закрытых частей. Оценка после исполнения
  и после следующего market tick должна использовать одну базу LIFO.
- Обязательное независимое кросс-ревью SOLID/чистоты кода добавлено в
  [AGENTS.md](../AGENTS.md) и [разработку](development.md).

## Проверки

Ниже сохранены результаты регрессии и предшествовавшего инцидента;
актуальный результат развёрнутого окружения приведён выше.

Итоговая регрессия: 937 Python-тестов на
отдельном PostgreSQL 16, 48 тестов инструментов develop. Frontend: 74 теста,
TypeScript и production build.
Python wheel/sdist собираются, содержат Analytics и исключают develop.
Ruff и Black прошли. Добавлены регрессии безопасной диагностики ошибок
и продолжения reconnect при ошибках свойств SDK-исключения.

Сквозные синтетические сценарии используют настоящий Analytics ASGI/HTTP
клиент, Worker composition, SQLite, durable batch и Core fact ingress:
две позиции до исполнения, истечение TTL после commit и outage/recovery.

Операционная проверка Core → Analytics при остановленном Worker:
шесть инструментов после прогрева FRESH; 94–120 свечей в окне, максимальный
возраст стакана около 1038 мс, максимальная задержка прогревающего запроса
48 мс. Семь пар повторных чтений одного поколения сохранили метрики.
HTTP-ошибок не было. Это измерение до последнего перезапуска Core,
не нагрузочный SLA и не подтверждение текущей работоспособности.

Восстановление P&L выполнено после штатной остановки Worker и доставки остатка
outbox. Исправлены четыре исполнения в двух группах: восемь строк Worker и
одиннадцать Core. Независимая проверка всех изменённых строк и единиц цены
не обнаружила расхождений; оба журнала имеют статус COMPLETE. Повторный dry-run
не обнаружил новых исправлений. Исходные события и исторический аудит сохранены.

Проверка 11:14 UTC: все шесть инструментов UNAVAILABLE, счётчик решений Worker
не изменился; незавершённых intents нет. Очередь фактов за время проверки
опустела. Изолированный SDK source без gateway воспроизводит сброс stream
(`AioRequestError`, `CANCELLED`, категория `CONNECTION_RESET`), при этом история
свечей читается. Это локализует сбой в stream-тракте, но не устанавливает его
точную внешнюю причину. Повторяемая проверка доступна в
`develop/scripts/check_analytics_runtime.py`; одного health недостаточно
для закрытия этой приёмки.

Сравнительная проверка stream API: bidirectional stream возвращает
`CANCELLED / RST_STREAM 8`, серверный stream на настроенном sandbox endpoint —
`UNIMPLEMENTED`. Позднейшая проверка Node подтвердила gRPC 12 перед сбросом;
точный сервер или маршрутизатор, сформировавший ответ, не локализован.
`develop/scripts/check_market_source_transport.py` воспроизводит проверку
с ограничением ожидания 15 секунд на каждый параллельный запрос.
Оба скрипта выводят только диагностические коды и агрегаты.

Дополнительный контроль обходит менеджер подписок и преобразования SDK,
вызывая тот же bidirectional RPC напрямую через stub: RST_STREAM 8 получен
через 442 мс, до истечения таймаута. Отдельный `GetUserTariff` показал
MarketDataStream open=0 при limit=32; остальные счётчики открытых потоков
также нулевые. Исчерпание одновременных потоков этим замером не подтверждается;
по документации брокера обновление счётчиков может отставать на две минуты.
Это не измерение общего числа запросов с внешнего IP. Для проверки только
тарифных счётчиков скрипт поддерживает `--tariff` и не создаёт подписки.

После развёртывания окончательного Core повторная проверка 11:21 UTC дала
тот же результат: UNAVAILABLE 6, прирост решений 0, очередь фактов опустела.
Все шесть Compose-сервисов запущены, четыре настроенных healthcheck проходят,
Core подтверждает совместимость схемы. Временный тестовый PostgreSQL удалён.
На тот момент операционная приёмка оставалась открытой: требовались FRESH
по активным инструментам и продвижение решений Worker. Их последующее
восстановление подтверждено в заключительной проверке выше.

## Кросс-ревью

- `analytics_boundary_audit` проверил Analytics по контрактам, SOLID и чистоте
  кода. Исправлено изменение метрик внутри неизменного snapshot на временной
  границе готовности свечей.
- `analytics_contract_audit` независимо проверил Worker, UI, Core gateway,
  lifecycle, Docker/Compose и SDK price conversion. Исправлены пропущенная
  проверка TTL при bootstrap, блокировка свежих котировок после ошибки
  периодической истории и прекращение reconnect после ошибки закрытия SDK.
- Дополнительный обзор Net P&L выявил разные базы себестоимости между
  terminal snapshot и следующим tick; исправление прошло повторное ревью
  `analytics_contract_audit`.
- Восстановление данных проверил `decision_test_matrix`: APPROVED после
  исправлений округления и сохранения рыночной оценки. PostgreSQL-проверка
  потерянного подтверждения и повторного применения также прошла.
- Правило кросс-ревью и документы проверил `analytics_contract_audit`;
  диагностический Worker probe — `decision_test_matrix`. Исправлена
  устойчивость диагностического кода к ошибкам SDK accessor; root независимо
  проверил исправление, полная регрессия прошла. Исправление отдельного запуска
  develop-тестов также прошло независимое ревью.
- Изолированный stream transport probe проверил `decision_test_matrix`:
  APPROVED; ограничение 15 секунд относится к каждому RPC-чтению, а не
  ко всему процессу подключения и очистки.
- HTTP/2 controls и reflection проверил `decision_test_matrix`: APPROVED,
  Ruff/Black и Node syntax check прошли. Эти скрипты находятся в develop.
- Восстановление решений, подтверждения outbox и соответствие DoD независимо
  проверил `analytics_boundary_audit`: APPROVED с ограничением свежести выше.

## Ограничения

Подписки объединяются до закрытия/ротации источника; удаления простаивающих
подписок пока нет. Структурно некорректный JSON отклоняется целиком, обычные
невалидные инструменты изолируются внутри пакета. Health Analytics подтверждает
работу процесса, свежесть рынка проверяется отдельно для каждого снимка.
