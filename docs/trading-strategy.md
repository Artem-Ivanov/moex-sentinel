# Торговая стратегия

Для всех автоматов применяется один определённый кодом алгоритм динамической
стратегии. Analytics рассчитывает адаптивные пороги отдельно для каждого
инструмента, Worker использует их при принятии решения. Стратегия не является
сущностью БД; общие значения окружения читаются при старте Worker.

Шаг усреднения и минимальный порог чистой прибыли зависят от медианы модулей
процентных изменений закрытия завершённых минутных свечей: шаг равен максимуму
из 0,10% и удвоенной медианы, порог прибыли — максимуму из 0,05% и медианы.
Для адаптации нужно не менее 15 свечей. При недостаточной или устаревшей
истории применяются резервные значения окружения. Подтверждение покупки
дополнительно требует непрерывного окна из 20 свечей.

Показатели относятся к одному рыночному снимку. Изменение входных свечей может
изменить пороги следующего решения; уже записанное решение и факты его заявки
сохраняют исходные данные. `strategy_snapshot` содержит исходные настройки
решения, `indicators` — фактически применённые адаптивные значения и их источник.

Ресурсы учитываются через общий размер покупки, свободные средства счёта и
резервы активных заявок, восстанавливаемые после перезапуска. Индивидуального
бюджета позиции нет; по решению пользователя веха 0.7 сохраняет текущие поля.

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `STRATEGY_BUY_ORDER_LOTS` | `1` | Лотов в одной покупке |
| `STRATEGY_STOP_LOSS_PERCENT` | `5` | Закрытие позиции при допустимом минусе |
| `STRATEGY_TAKE_PROFIT_PERCENT` | `6` | Полная фиксация чистой прибыли после комиссий |
| `STRATEGY_AVERAGING_STEP_PERCENT` | `0.5` | Резервный шаг усреднения при отсутствии адаптивного расчёта |
| `STRATEGY_PARTIAL_TAKE_PROFIT_PERCENT` | `0.5` | Резервный порог чистой прибыли при отсутствии адаптивного расчёта |
| `STRATEGY_PARTIAL_SELL_PERCENT` | `25` | Доля лотов частичной продажи |
| `STRATEGY_MAX_PARTIAL_SELL_STEPS` | `3` | Число ступеней частичной фиксации |
| `STRATEGY_ORDER_TTL_SECONDS` | `10` | Время ожидания заявки до сверки/отмены |
| `STRATEGY_ORDER_RETRY_LIMIT` | `3` | Число безопасных повторов операции с заявкой |
| `STRATEGY_CORE_RETRY_LIMIT` | `5` | Число повторов доставки фактов в Core |
| `STRATEGY_ENABLED` | `true` | Разрешение создавать новые торговые intent |

Ограничений на общую сумму позиции, минимальный свободный остаток и максимальное число усреднений нет. Докупка разрешена только при одновременно выполненных условиях тренда/скользящей средней и наличии фактических свободных средств на `STRATEGY_BUY_ORDER_LOTS`. Если средств нет, Worker возвращает WAIT и продолжает наблюдение. Отдельный сигнал для усреднения не вводится.

Сигналы выхода сохраняются: stop-loss, полное достижение take-profit и частичная фиксация прибыли. Открытая брокерская позиция после bootstrap обрабатывается тем же алгоритмом, что и позиция, открытая Worker.

При `STRATEGY_ENABLED=false` supervisor, heartbeat, сверка заявок и доставка уже созданных фактов продолжают работать, но новые intent не создаются. Это режим безопасной остановки торговли перед переключением.

Лимит заявок расходуется после расчёта решения только для BUY_MORE, SELL_PART
и SELL_ALL. WAIT/NO_ACTION не занимают ёмкость лимита и сохраняют вычисленное
состояние. Это позволяет следующим инструментам обрабатываться, когда первые
позиции в очереди ожидают условия входа или выхода.

## Подтверждение покупки

Стакан проверяется до наблюдения минимума и решения. Пустой, inconsistent,
crossed, просроченный, будущий либо структурно некорректный стакан не создаёт
заявку и не меняет цикл. Возраст считается на момент атомарного рыночного
snapshot; граница две секунды включается. Положительные конечные цены,
положительные количества и порядок всех уровней обязательны.

Микро-окно определяется существующими индикаторами: SMA5/SMA20, изменение за
10 свечей и диапазон завершённых минутных свечей. Последние 20 свечей должны
быть последовательными. Повторы одной свечи не увеличивают окно; конфликтующие
записи одного времени исключаются. После разрыва истории покупка ожидает новое
полное окно (`BUY_WINDOW_UNCONFIRMED`). Ровный диапазон допустим для боковика.

Первая покупка и усреднение требуют наблюдённого минимума и последующего
разворота не менее максимума из двух ценовых шагов и половины адаптивного
шага усреднения. Первое наблюдение при пустом минимуме даёт WAIT. Сохранённый
минимум продолжает цикл после перезапуска, но не заменяет готовность окна.

Падающий тренд блокирует обе покупки. Если ask выше SMA20 и находится в верхней
четверти диапазона, применяется `BUY_UPPER_RANGE_FILTER`, включая первичный вход.
Для усреднения именно исполнимая цена ask должна достичь шага снижения от
последней покупки. Доступные средства проверяются вместе с комиссией покупки.

## Выход и состояние после исполнения

Stop-loss сохраняет прежний ценовой порог и приоритет. Полный take-profit
сравнивает установленную цель с прибылью по best_bid после обеих комиссий;
из комиссии покупки учитывается доля оставшихся лотов. До достижения полной
цели допустима существующая частичная продажа по чистой прибыли лота.
Формулы адаптации, общие защитные пороги и размер заявки сохраняют текущую
семантику; фактические адаптивные значения продолжают зависеть от рынка.

Ненулевое исполнение BUY очищает наблюдённый минимум и сохраняет свечу решения:
в той же свече новая покупка запрещена (`BUY_CANDLE_COOLDOWN`). SELL очищает
минимум и выключает готовность следующей частичной продажи до существующего
условия retracement/progression. Эти изменения коммитятся вместе с intent,
лотами и outbox. Повтор исполнения не меняет цикл; отмена без исполнения также
его не меняет. Для старых intent без свечных metadata используется минута
исполнения. Повторные WAIT/audit разрешены, повторный активный intent — нет.

Временная нестабильность цены сама по себе не вводит новый фильтр: в этой вехе
проверяются структурная корректность, consistency и свежесть стакана.

## Net P&L

Отображаемый `Net P&L` равен реализованному результату после комиссий плюс
нереализованный результат по текущей цене минус комиссия покупки оставшихся
открытых лотов. Её доля для каждого лота: `entry_commission × remaining_lots /
original_lots`. Комиссии уже закрытых лотов повторно не вычитаются; будущая
комиссия продажи не является фактическим расходом и в эту метрику не входит.
Поле `Unrealized` остаётся результатом до комиссий. Одинаковый расчёт применяется
после исполнения заявки и при последующем обновлении котировки.
Средняя цена, вложенная сумма и нереализованный результат этого снимка
рассчитываются по оставшимся LIFO-лотам Worker. Средняя цена брокерского
портфеля может отличаться после частичной продажи; она не подменяет стоимость
оставшихся лотов в P&L. Входные данные торговой стратегии при этом не меняются.
