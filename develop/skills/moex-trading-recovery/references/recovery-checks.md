# Проверка результата и доступные средства

Пути указаны относительно найденного корня проекта. Перед запуском прочитай актуальные исходные файлы: названия сервисов, context, API, схемы и параметры меняются. Эта карта не фиксирует конкретные broker/account/automation ID или Docker context.

## Что считать восстановлением

| Наблюдение | Проверка и вывод |
|---|---|
| Healthy, HTTP 200, IN_WORK | Только инфраструктура/lifecycle. Нужны свежие решения и проверенные входы/guards по каждому автомату. |
| Свежий WAIT/NO_ACTION | Нормальная работа, когда reason соответствует входам момента решения и состояние рынка проверено. Старый WAIT не доказывает текущую работу. |
| Закрытая сессия, недоступный рынок | Подтверди текущий статус и свежую работу защитного/диагностического цикла. Если новая decision не создаётся по контракту, отчитай «ожидает рынок; принятие решений после открытия ещё не проверено», не общий успех торговли. |
| Нет заявок | Проверь достаточность сигнала, cash, commissions, intent, cooldown и рынок; отсутствие заявки само по себе не дефект. |
| Один новый PENDING без retries | Может быть нормальной очередью. Сравни несколько выборок, возраст старейшего, продвижение sequence/ACK и Core. Пустая очередь без новых решений также не доказывает работу. |
| Растут retries/старые PENDING | Проследи reject/transport/envelope/idempotency; не очищай очередь, чтобы сделать индикатор зелёным. |
| Worker consistent, Core пуст | Сверь брокерские лоты, bootstrap/fact и принятие Core. Worker reconciliation не является подтверждением Core. |
| Новая неизвестная ошибка | Сохрани очищенные доказательства, останови изменения наугад. При неполной причине итог — диагностика/ограничение, не восстановлено. |

Заранее выбери конечное окно наблюдения по реальному tick/retry/session поведению. Проверь несколько циклов, а не одно удачное чтение; длинный мониторинг запускай с доступными прогресс-обновлениями. Если окно закончилось без достаточных доказательств, явно обозначь недоказанные позиции. Последовательные чтения не являются атомарным снимком.

## Карта проекта

- `develop/skills/moex-trading-audit/references/runtime-sources.md`: API, таблицы и безопасный сбор. Предпочитай reference установленного audit skill, если он актуальнее; разрешай различия по текущему коду.
- `develop/scripts/capture_recovery_state.py`: ограниченный снимок API/Worker/Analytics. Прочитай реализацию до использования: текущая версия содержит defaults конкретного запуска, фиксированный context/URL и LIMIT. Укажи новый output, проверь окружение, pagination и полный охват позиций; при несовпадении адаптируй проектную копию. Это не полный Core DB аудит.
- `develop/scripts/capture_audit_runtime_metadata.py`: candidate для метаданных runtime. Проверь allowlist, выбранные сервисы и соответствие работающего образа анализируемому коду.
- `develop/scripts/observe_worker_progress.py`: ограниченное наблюдение счётчиков decision/outbox в read-only SQLite. Агрегаты дополни сведениями по каждой позиции; одна активная позиция может скрыть остановку остальных.
- `src/trading_automaton/services/analytics_runtime.py`, `position_batch_scheduler.py`, `streaming_batch_tick.py`: admission, clock, expiry и dispatch deadline.
- `src/trading_automaton/services/position_bootstrap.py`, `fact_synchronization.py`, `src/sentinel_contracts/`, Core обработчики фактов: согласованность позиции, envelope, revision/sequence, ACK. Найди действующие обработчики через `rg`, не предполагай старую схему.
- `compose.yml`, `docker/`, `pyproject.toml`, `uv.lock`, соответствующие `tests/`: scope сборки и воспроизводимые проверки. Изменение общего пакета может затронуть несколько образов; включай только фактически затронутые и разрешённые сервисы.

Скрипты — доступные кандидаты, а не обязательные команды. Не копируй их в skill и не запускай repair/seed/migration помощники по одному названию. Прочитай побочные эффекты, сравни с текущей задачей и разрешениями.

## Пример диагностики часов

При `frame.captured_at < book.captured_at <= evaluation_now` метка стакана не находится в будущем относительно оценки. Проверь, какие часы использовали admission и downstream guards одного snapshot. Если они различаются, воспроизведи контракт тестом и исправь доказанную точку сравнения. Срок годности должен оставаться привязан к исходным данным; перенос `expires_at` на `now + TTL` омолаживает устаревающий источник. Если текущий код уже соблюдает этот контракт, не повторяй старый патч: проверь clock skew, реальную freshness и другие входы.

Перед любым запуском вспомогательного скрипта сначала прочитай исходник. Даже `--help` может выполнить действия верхнего уровня, если CLI не обрабатывает этот флаг; используй его только после проверки отсутствия побочных действий.
