# Локальные материалы разработки

Размещайте здесь временные скрипты, отчёты и эксперименты, не входящие в приложение. Не включайте секреты, реальные пользовательские данные или рабочие дампы.

`CURRENT.md` — краткая локальная точка продолжения, `WORK_LOG.md` — дополняемый локальный журнал. Они игнорируются Git и могут отсутствовать в новом checkout. Проверяйте `git status --short`; существующий CURRENT не перезаписывайте. Создайте его из шаблона:

```sh
test -e develop/CURRENT.md || cp develop/CURRENT.example.md develop/CURRENT.md
```

Сверяйте статус с кодом и проверками; неизвестный runtime помечайте неизвестным. Старые записи не подтверждают текущее состояние.

## Codex hooks

Шаблон `.codex/` может содержать хуки с зависимостью Python 3 и `sh`; для Windows требуется Git Bash. Перед включением вручную прочитайте конфигурацию и команды, проверьте пути/права и согласуйте их с политикой машины. Доверие проекту и конкретным hooks настраивается по [официальной инструкции hooks](https://learn.chatgpt.com/docs/hooks), включая команду `/hooks`; это не было проверено в целевом проекте. Не заявляйте автоматический trust. Не помещайте секреты в hook-команды или вывод.

Пакет уже содержит canonical skill `.agents/skills/planning-with-files/`; отдельная установка не нужна. Из корня проекта проверьте шаблон и создайте первый план:

```sh
python3 develop/check_template.py
sh .agents/skills/planning-with-files/scripts/init-session.sh "Первая задача"
```

Скрипт напечатает точный `PLAN_ID`; используйте именно его. До нового сеанса в окружении host задайте абсолютный `PWF_PLAN_ROOT=$PWD` и этот `PLAN_ID`, чтобы hooks и сессия использовали один план. Скрипт создаёт `.planning/` относительно текущего каталога, поэтому запускайте команду из корня проекта. Сам шаблон не копирует локальные журналы, старые планы или runtime-данные.
