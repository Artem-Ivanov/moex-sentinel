# Контекст проекта

Читай сведения по задаче, а не весь архив. `AGENTS.md` задаёт обязательные правила; `develop/CURRENT.md`, если существует, передаёт локальный статус; `develop/WORK_LOG.md` может отсутствовать и читается выборочно. Скилл не заменяет правила проекта.

1. В начале прочитай `develop/CURRENT.md`, если он есть, и проверь `git status --short`. В новом checkout прочитай `README.md`, `AGENT_BRIEF.md` и нужные разделы `docs/implementation-plan.md`; затем создай CURRENT из `develop/CURRENT.example.md`, не заменяя существующий и не указывая неизвестный runtime как проверенный. Сверь состояние по текущим файлам и проверкам.
2. Выбирай контекст по теме: границы и постоянные решения — `AGENT_BRIEF.md` и тематические документы; очередь — `docs/implementation-plan.md`; конкретная веха — её постановка и связанные доказательства из CURRENT. Для WORK_LOG найди нужный заголовок и прочитай только эту запись. Не загружай весь журнал по умолчанию.
3. После значимого результата/проверки/решения/блокировки и перед завершением передай root факты и ссылки для общего CURRENT/WORK_LOG. Root обновляет общий контекст; исполнители не перезаписывают его параллельно. Важные решения сохраняются в подходящем tracked документе. Не переносить длинные логи, секреты или старые промежуточные статусы в CURRENT.

Если CURRENT расходится с checkout или результатами свежей проверки, сообщи root подтверждённые данные и расхождение. Не выдавай старые отчёты за актуальное состояние. Cross-review выполняется по `AGENTS.md`.
